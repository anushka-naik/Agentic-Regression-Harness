# Data card: northstar-judge-v1

A 60-response corpus for calibrating the **advisory** judge. Generated by
`scripts/prepare_judge_review.py`. CC0-1.0 (see `DATA_LICENSE`). Entirely synthetic.

| | |
| --- | --- |
| Families | 30 from the dev and validation splits of `northstar-retail-v1` (never held-out) |
| Responses | 60: one supported and one deliberately flawed per family |
| Splits | `calibration.jsonl` (15 families, 30 responses), `evaluation.jsonl` (15 different families, 30) |
| Supported responses | final answers from the scripted reference policy's traces |
| Flaw types | wrong_amount, wrong_order, fabricated_action, unsupported_certainty, contradictory_reason, misleading_recovery |
| `proposed_label` | construction label (`acceptable` / `flawed`), **not** a human judgement |

## Review status

**No human labels yet.** `review.csv` has empty `human_label`, `reviewer_id` and
`reviewed_at` for every row. `agentcheck judge-calibrate` reports
`Calibration pending: no verified human labels` until a person fills them in and imports
them with `agentcheck labels-import`. A coding agent must never fill these fields.

## Limitations

- Flaws are injected into otherwise templated text, so they are easier to spot than
  natural mistakes.
- Supported responses come from a rule-based policy, not a language model.
- 15 evaluation families make any agreement estimate exploratory.
